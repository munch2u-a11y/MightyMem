# Context Loom Architecture & Subsystems

Context Loom is a source-preserving, deterministic memory and context compilation engine designed for autonomous AI agents.

## Core Architectural Pillars

```
┌─────────────────────────────────────────────────────────────┐
│                      User Dialogue Input                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
               ┌───────────────▼───────────────┐
               │    X-Membrane & Shadow-X      │
               │   (Keyphrase & N-Gram Index)  │
               └───────────────┬───────────────┘
                               │
               ┌───────────────▼───────────────┐
               │     Y-Cypher Concept Graph    │
               │   (Vector Concept Vault Nodes)│
               └───────────────┬───────────────┘
                               │
               ┌───────────────▼───────────────┐
               │  3-Section JIT Context Packet │
               │  - [ASSERTED & DERIVED]       │
               │  - [BOUNDED PERSONAL]         │
               │  - [RECENCY & CONVERSATION]   │
               └───────────────────────────────┘
```

### 1. Source Preservation & Record Classification
All dialogue turns, tool outputs, and observations are assigned immutable UUIDs and categorized into explicit `RecordKind` types:
- `USER` / `PREFERENCE`: Dialogue turns and user-reported behavioral tendencies.
- `ASSISTANT`: Unverified model statements.
- `OBSERVATION` / `TOOL_RESULT`: Tool execution outputs tagged with `EvidenceStatus.TOOL_VERIFIED`.
- `FACT`: Derived factual statements (`EvidenceStatus.SYSTEM_DERIVED`).

### 2. Dual-Axis X-Membrane & Y-Cypher Indexing
- **X-Membrane**: Tracks keyphrase and n-gram activation frequencies across turns.
- **Y-Cypher Vaults**: Non-language vector concept nodes generated by compacting multi-turn conversation dynamics without raw text pollution.

### 3. Deterministic 3-Section JIT Context Rendering
When a query is received, `ContextCompiler` evaluates candidate records across retrieval lanes and admits top-utility evidence into three distinct sections:
1. `[ASSERTED & DERIVED EVIDENCE]`: Grounded facts and tool-verified observations (`TOOL_VERIFIED`).
2. `[BOUNDED PERSONAL CONTINUITY]`: Explicit user preferences and identity traits.
3. `[RECENCY & CONVERSATIONAL CONTINUITY]`: Recent dialogue turns and unverified assistant statements.

This strict ordering prevents model hallucinations and enforces evidence-based reasoning.

### 4. The Tool Use Cortex & Evidence Verification Engine
The **Tool Use Cortex** connects local execution runtimes (`BoundedFileRuntime` / Python tools / shell scripts) with Context Loom's memory store:

```
┌─────────────────┐    1. Execute Tool    ┌─────────────────────────┐
│ Local LLM Agent │ ────────────────────► │  Tool Use Cortex        │
└────────┬────────┘                       │  (Python/Shell Runtime) │
         │                                └────────────┬────────────┘
         │                                             │ 2. Return Output & Log
         │ 4. Read Verified Receipt                    ▼
         │    [VERIFIED OBSERVATIONS]     ┌─────────────────────────┐
         └─────────────────────────────── │ Context Loom Storage    │
                                          │ (TOOL_VERIFIED Record)  │
                                          └─────────────────────────┘
```

- **Unverified Assistant Claims (`UNVERIFIED`)**: When an LLM outputs text (e.g. *"I executed the script"*), it is tagged as `RecordKind.ASSISTANT` with `EvidenceStatus.UNVERIFIED`.
- **Verified Tool Observations (`TOOL_VERIFIED`)**: When a tool executes on the host, its stdout and file receipts are logged as `RecordKind.OBSERVATION` with `EvidenceStatus.TOOL_VERIFIED`.
- **Admittance Guarantee**: The compiler prioritizes `TOOL_VERIFIED` observations in `[ASSERTED & DERIVED EVIDENCE]`. Small local LLMs can read these execution receipts to confidently state true tool outcomes without hallucinating.
